# Os cinco projetos de teste

> **Proposta — a validar com o orientador.**

Escolhidos para variar tamanho, tipo de entrega e risco. Não são usados durante a construção
(E2–E7): só entram na validação, para a régua não ser ajustada ao sistema.

| # | Projeto | Pedido (resumo) | Tamanho | Pronto quando |
|---|---|---|---|---|
| P1 | Lista de tarefas em linha de comando | "Um programa de terminal para adicionar, listar, concluir e remover tarefas, salvas em arquivo." | pequeno | os quatro comandos funcionam e os testes passam |
| P2 | API de biblioteca | "Uma API REST para cadastrar livros e leitores e registrar empréstimos e devoluções, com banco de dados." | médio | CRUD + regra de empréstimo (sem livro emprestado duas vezes) testados |
| P3 | Relatório a partir de planilha | "Ler um CSV de vendas, validar as linhas e gerar um relatório com totais por mês e por produto." | pequeno | linhas inválidas são apontadas; totais conferem com um gabarito |
| P4 | Site de portfólio | "Um site estático de três páginas (início, projetos, contato), responsivo e acessível." | médio | as três páginas existem, passam numa checagem de acessibilidade e têm captura de tela |
| P5 | Apresentação a partir de dados | "Uma apresentação de 8 slides sobre os resultados de P3, com um gráfico por slide de dados." | pequeno (não-código) | os 8 slides existem e cada número confere com o relatório de P3 |
